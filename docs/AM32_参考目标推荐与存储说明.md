## 本轮范围

用户要求先解决参考目标选择，随后由用户列出引脚表，本对话负责核对。反电动势电路、DRV8323S 原理图及电流/电压采样的详细设计暂缓；本轮不替用户完成整张引脚表，也未开始修改或烧录固件。

用户进一步明确使用 STM32G071CBT6、按 128KB Flash 规划，因此本版主参考确定为 `GEN_128K_G071`。64KB 布局仅保留为对照，不再作为本板默认方案。

## 推荐顺序

### 1. GEN_128K_G071：本板主参考

使用 `HARDWARE_GROUP_G0_A`，没有 `SIXTY_FOUR_KB_MEMORY` 定义。G071 公共配置因此将参数地址设为 `0x0801F800`；核心控制走高、低侧分别控制的分支，DShot 参考输入为 PB4、TIM3_CH1。

优点：配置意图与当前 STM32G071CBU6 的 128KB 容量及用户要求对应；通用配置较简洁，便于形成自己的板级目标，并为后续 SPI、故障诊断和调试功能保留程序空间。

待解决项：名字中的 128K 不会自动使所查 GCC 构建脚本切换到完整的 128KB 布局。v2.21 的 G071 默认 `.ld` 文件仍将 EEPROM 与固件名称信息放在 64KB 范围内，需要将目标定义、链接脚本、bootloader 和配置工具统一核对。该问题作为本板移植工作解决，不能据此认定 128KB 芯片不适用或目标无法使用。

建议用途：本板源码与引脚的主要起点。最终建立自有 target，而不是直接刷入通用 HEX。

### 2. GEN_64K_G071：存储布局对照

同样使用 `HARDWARE_GROUP_G0_A`，但定义了 `SIXTY_FOUR_KB_MEMORY`，参数起点为 `0x0800F800`。核心桥臂和 DShot 布局与主参考一致。

优点：有助于对照 64KB 与 128KB 配置的差异，其参数起点与所查默认 GCC 脚本一致。

缺点：如果选用该软件布局，将暂时只利用本 MCU 的部分 Flash，偏离本轮按 128KB 规划的要求。地址起点一致也不代表无需核对应用上界、元信息与擦除区域。

建议用途：仅作配置和构建文件对照，不作为本板默认容量方案。

### 3. AM32_ESC_G071：较具体的板级配置参考

同样使用 `HARDWARE_GROUP_G0_A`，采用 64KB 参数布局；该目标显式指定电压 ADC 为 PA4、电流 ADC 为 PA6，并启用 LED strip 等配置。这里只记录现成目标的区别，不替本板确定采样接法。

优点：展示了如何在通用硬件组上覆盖具体板级配置，适合用户列出引脚表后对照目标定义。

缺点：默认死区、电流换算、ADC 和 LED 配置属于该目标，不能因名称含 AM32 就当成适用于任意自制板；PA6 等资源还需与本板其他外设核对。它也不构成 DRV8323S 专用固件已完成的证据。

建议用途：补充参考板级配置的组织方式，不优先整套照搬。

### 条件备选：PWM_ENABLE_G071

使用 `HARDWARE_GROUP_G0_B` 与 `PWM_ENABLE_BRIDGE`，采用每相 PWM＋每相使能的控制分支。它可作为将来研究另一种驱动输入接口的参考；当前本版按 6x PWM 路线推进，不把它作为主参考。

此目标中的“每相使能”不能与 DRV8323S 的单个全局 ENABLE 引脚混淆，三相 PWM＋三相使能仍占六个 MCU 信号。若改变路线，需重新核对驱动器真值表和固件行为；本轮不展开该电路设计。

## 当前建议

采用固定版本 v2.21，主参考 `GEN_128K_G071`；用 `GEN_64K_G071` 对照存储差异，用 `AM32_ESC_G071` 对照板级配置写法。当前MCU为 STM32G071CBU6，按 128KB 规划；最终为自制板建立独立 target，保留自己的名称和硬件定义。

最初比较依据为目标定义、构建文件、链接脚本和发布元数据；后续已实际下载并编译参考目标，候选存储修订通过链接检查。当前仍未完成本板适配或样机验证。

## 三个存储区域为什么要分开

它们都是 MCU 内部 Flash 中的软件区域，不是额外三颗芯片，也不是 STM32 强制规定必须这样分区。

| 区域 | 做什么 | 分开的原因 |
| --- | --- | --- |
| bootloader | 上电检查、接收固件更新并进入应用 | 更新应用时保留更新入口；其 MCU、信号输入和协议需要匹配 |
| 应用程序 | 运行 AM32：DShot、启动、换相与保护等 | 主程序拥有明确入口和可用空间，升级时避免覆盖其他区域 |
| 参数存储区 | 保存方向、启动/换相设置、限流等持久化参数 | Flash 按页擦除，存参数时应避开程序代码；升级保留参数需取决于工具和版本兼容性 |

AM32 源码常用 EEPROM 命名该区域；对这里的 G071 实现，它是保留的内部 Flash，不表示必须加外部 EEPROM。

所查 G071 目标中，应用入口定义为 `0x08001000`，即预留起始 4KB 给普通 bootloader 路径；64KB 与 128KB 配置分别将参数起点定义为 `0x0800F800` 与 `0x0801F800`。这些是源码中已确认的值，不能忽略实际链接脚本与 bootloader 的一致性后直接拿来烧录。

按本板的 128KB 规划，应核对并落实的候选区域边界是：

| 区域 | 拟核对的地址范围 |
| --- | --- |
| bootloader，4KB | `0x08000000`～`0x08000FFF` |
| 应用及其元信息，122KB | `0x08001000`～`0x0801F7FF`，末尾还要保留固件名称等元信息 |
| 参数页，2KB | `0x0801F800`～`0x0801FFFF` |

该表是需要统一实现的候选布局，不是已通过链接映射与 bootloader 审查的烧录地址表。特别要复查应用链接上界、元信息占位和参数页不重叠；不能仅因参数起点一致就宣布布局全部正确。

## 首次为什么用 SWD，以及基本方法

SWD 是 ST-LINK 等调试器访问 MCU 的硬件通道，能直接烧录、调试和恢复空白芯片。bootloader 是芯片内运行的软件，负责后续 AM32 更新流程；两者不是同一个东西。AM32 官方空白 ESC 安装流程先用调试器安装匹配的 bootloader，再安装主固件。

首次烧录的计划流程：

1. 板上引出 SWDIO、SWCLK、GND、目标电压参考 3V3、NRST；核对调试器供电方式，避免两个电源互相供电。
2. 在桥臂保持安全状态、板载 3.3V 已验证的条件下，用 ST-LINK 和 STM32CubeProgrammer 通过 SWD 连接，读取器件信息。
3. 选择与 G071、最终信号输入脚及存储布局一致的 bootloader；本组参考目标输入为 PB4，但具体 bootloader 版本/文件尚未确定。
4. 烧录 bootloader 并校验，再烧录与本板匹配的应用并校验。HEX 自带地址，BIN 需按已核对的布局设置地址。
5. 初始化或核对参数，再检查复位后的启动行为。首次板级测试先验证通信和控制逻辑，不能把通用目标的现成 HEX 当成本板最终电机固件。

参考：[AM32 安装说明](https://github.com/am32-firmware/AM32/blob/main/README.md)、[AM32 bootloader 仓库](https://github.com/am32-firmware/AM32-bootloader)、[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)。

## 用户提供引脚表后的核对范围

检查 MCU 物理脚号/复用、TIM 与 DMA 资源、参考目标宏定义、DShot 与 bootloader 输入，以及 SPI/调试接口的冲突。对暂缓的三项电路只保留必要资源约束，不提前定外围电阻、电容或布线。
