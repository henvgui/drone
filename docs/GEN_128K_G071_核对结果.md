# GEN_128K_G071 实际核对结果

日期：2026-10-26。范围：参考目标、构建与存储布局、Bootloader 匹配及升级可靠性机制。按用户要求，本轮未展开反电动势电路、DRV 原理图或电流/电压采样设计。

## 结论

`GEN_128K_G071` 可继续作为当前 STM32G071CBU6 自制 ESC 的主参考。2026-10-28用户将原STM32G071CBT6的LQFP48封装改为CBU6的UFQFPN48，128KB容量和本报告存储布局保持不变。本轮此前已下载固定版本源码并实际编译；发现并制作了 128KB 链接布局候选修订，实编译结果确认应用入口保持不变、固件名称元信息移到正确位置。

这仅确认参考目标可构建及候选存储布局一致，尚未确认自制板引脚、DRV8323S 初始化和实际电机运行。当前产物不作为可直接上板驱动电机的发布固件。

V1 开发下载主路径建议采用 **ST-LINK＋STM32CubeProgrammer＋下载后校验**。单线升级是有线升级的一种，保留原协议兼容性，但建议不列为第一版必须完成的独立验收功能。

## 2. 存储布局问题与实际编译

固定版本默认 GCC 链接脚本将 EEPROM 区放在 `0x0800F800`，固件名称区随之位于 `0x0800F7E0`，而 GEN_128K_G071 的目标参数地址为 `0x0801F800`。默认程序空间边界也需检查，不能根据脚本注释写着 128KB 就认定布局完整一致。[上游链接脚本](https://github.com/am32-firmware/AM32/blob/6b3ef3d15228e8d70244bd6e3bd87c7eac939d6f/Mcu/g071/STM32G071GBUX_FLASH.ld)

已经新增候选链接文件 `firmware/linker/stm32g071cb_128k_candidate.ld`：把参数区移至 `0x0801F800`，把应用区域大小统一到 122KB 区间并扣除元信息及向量区；保留上游 16KB RAM 分配，未顺便改变其他资源。增加链接期断言，检查应用、元信息和参数区边界。

本机使用已有 Arm GNU Toolchain 12.2.1，按上游源文件集合与主要编译选项进行实际构建：

1. 严格沿用编译选项时，GCC12 对程序读取低地址 Flash 别名中的 Bootloader 信息报 array-bounds，因 `-Werror` 而失败；日志保留于 `build/am32-audit/upstream/build.log`。
2. 针对该低地址映射添加 `--param=min-pagesize=0` 后，未修改上游 C 源码，默认布局编译链接成功。
3. 使用相同兼容参数和候选 128KB 链接文件，再次编译链接成功。

| ELF 实际检查项 | 默认布局构建 | 候选 128KB 布局构建 |
| --- | --- | --- |
| 向量表 | `0x08001000` | `0x08001000` |
| 固件名称区 `.file_name` | `0x0800F7E0` | `0x0801F7E0` |
| 名称区与 128KB 参数页的关系 | 不在参数页前32字节 | 正好位于参数页前32字节 |

构建仍有 nosys 主机系统调用桩与 RWX LOAD 段等链接警告，未宣称构建无警告。以上检查不代替硬件、时序与负载验证。

复算脚本：`python tools/build_am32_reference.py --name candidate-128k --low-address-flash --linker firmware/linker/stm32g071cb_128k_candidate.ld`。完整命令、源文件数、日志、ELF、map 与段表在 `build/am32-audit/`。机器可读摘要为 `calculations/am32_target_audit.json`。

## 3. 匹配的 Bootloader 已找到

核对 AM32-bootloader v19.0.0：G071 的默认容量是 128KB，另提供显式的 64K 构建；普通非 CAN 路径应用偏移为 4KB。PB4 的 128KB 发布文件是：

`AM32_G071_BOOTLOADER_PB4_V19.hex`

同一发布中也有带 `_64K_` 的文件。本板按 128KB 规划，匹配候选是前者；若用户最终改动 DShot 输入引脚，需同步重选 Bootloader。

源码给出的 128KB 参数地址为 `0x0801F800`，非 CAN 固件名称位置为参数地址减32，因此与候选修订一致。v19 还会检查参数页初始化标志和应用入口；首次安装不能只把参数页留空就认定启动准备完成，默认参数的生成/安装仍需在本板固件准备时落实。

已核对源码与发布文件名，尚未烧录或验证 v2.21 应用与该 Bootloader 的板级组合。

依据：[G071 默认容量](https://github.com/am32-firmware/AM32-bootloader/blob/v19.0.0/Mcu/g071/Inc/blutil.h)、[Bootloader 主程序](https://github.com/am32-firmware/AM32-bootloader/blob/v19.0.0/bootloader/main.c)、[构建配置](https://github.com/am32-firmware/AM32-bootloader/blob/v19.0.0/Makefile)、[v19 发布](https://github.com/am32-firmware/AM32-bootloader/releases/tag/v19.0.0)。

## 4. 用什么工具发送升级数据

| 方式 | 工具和连接 | V1 定位 |
| --- | --- | --- |
| SWD 有线下载 | PC＋ST-LINK＋STM32CubeProgrammer，接 SWD/GND/目标电压参考/必要的 NRST | 开发、调试、首次安装和恢复的主路径 |
| 电调信号线有线升级 | AM32 Configurator（am32.ca）或官方提供的离线配置工具，加匹配的单线适配连接，或支持透传的飞控 | 后续可选便利功能 |

主板没有 USB 接口时，不能只把 USB 线直接插到 MCU；两条路径都需要合适的中间设备。当前自制 G431 飞控尚未实现升级透传，因此不把“有一块飞控”视为已具备透传能力。

通过信号线升级本身就是有线升级。复用同一根信号线是减少维护接线，并非无线下载，也不是飞行中更新。升级会占用控制器并改写应用，维护流程要求电机停机，在台架条件下执行；飞行中不能依赖该控制器继续正常驱动电机。

工具入口：[AM32 安装与工具说明](https://github.com/am32-firmware/AM32/blob/main/README.md)、[AM32 Configurator](https://am32.ca/)、[离线工具源码](https://github.com/am32-firmware/Offline-Configurator)、[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)。

## 5. 对传输错误、丢包和校验问题的评估

用户提出有线传输也需验证、不能仅为方便就省略可靠性措施，这个判断成立。线材只决定传输媒介，可靠性还取决于协议和工具。

已在源码中看到：

- Bootloader 使用 CRC16 验证命令/数据，错误校验返回 `0xC2`，成功应答为 `0x30`；接收有效数据后才进入相应编程流程。
- 写入函数检查结果后返回成功或错误应答；提供带 CRC 与应答的 Flash 读回功能。
- 离线工具具有 ACK 等待、有限次数重试及失败处理，也有单独的 Verify Flash 读回比较入口。

CRC 用于发现传输错误，ACK/超时/重试用于处理未收到有效应答的情况，写后读回比较用于确认 Flash 内容。三者不能混为一个“绝不会丢包”的保证。所查离线工具的 Verify 是独立入口，不能仅凭写入成功提示就宣称已经逐字节读回一致。

本轮没有做丢包、断线、断电的故障注入测试，也没有证明完整映像校验、原子升级或旧固件自动回滚。中途断电可能留下不完整应用；Bootloader 保留且可通信时可能重刷恢复，否则使用 SWD。CRC 也不是固件签名或目标型号匹配检查。

依据：[Bootloader 协议与CRC实现](https://github.com/am32-firmware/AM32-bootloader/blob/v19.0.0/bootloader/main.c)、[离线工具 CRC 实现](https://github.com/am32-firmware/Offline-Configurator/blob/main/BF_ROOTLOADER.cpp)、[重试与独立读回验证](https://github.com/am32-firmware/Offline-Configurator/blob/main/widget.cpp)。所读副本保存在被忽略的 `references/am32-audit/`，作为当日源码证据。

## 6. 对本项目的建议与剩余工作

主参考继续使用 GEN_128K_G071，存储问题沿 128KB 路线处理，当前已有通过链接检查的候选文件。V1 下载以 ST-LINK＋CubeProgrammer 的有线下载和 Verify 为主；保留与匹配 Bootloader 的启动布局，不为绕过 Bootloader 另改一套启动方式。

单线升级只保留后续可用的接口与兼容性，不扩大为本版必须实现的新功能。用户已授权代选引脚，2026-10-27形成 [引脚分配表 A](ESC_V1.0_引脚分配表.md)，包括原生PA9/PA10所需的重映射处理、SPI2及PB12故障资源。DRV初始化及其他暂缓电路按原约定继续暂缓。完整板级固件、默认参数、上电与电机测试仍未完成。
