# ESC V1.0 下一步实施清单

日期：2026-11-02。当前前提：[方案基线](ESC_V1.0_方案冻结记录.md)已确定，[电气指标初稿](ESC_V1.0_电气指标与重量电流预算.md)已建立，[引脚分配表 D](ESC_V1.0_引脚分配表.md)采用STM32G071CBU6/UFQFPN48和MCU内部温度通道，原理图尚未完成。

最新工作范围：参考目标比较与构建核对已完成；用户随后授权本对话代选引脚，结果见引脚分配表。反电动势电路、DRV8323S外围原理图、电流/电压采样详细设计继续暂缓。以下保留总体步骤，未完成项不视为已验收。

本轮直接目标：完成 AM32 与硬件的接口定义，使原理图中的每条关键控制与反馈连接都有器件资料和固件配置依据。本文是实施清单；参考引脚不等于已确定的板级分配。

## 1. 固定固件参照与构建入口

记录 AM32 仓库、版本/提交、G071 参考 target、编译方法和工具版本。先编译原始参考 target，建立可重复的构建起点；再为本板新增或调整目标定义。

同时核对 bootloader 的 MCU/输入引脚、应用入口、链接脚本与参数存储区域。STM32G071CBU6 的 Flash 容量不能替代对目标固件内存布局的核对。保留 SWDIO、SWCLK、NRST、GND 和 3V3 调试接点，首次下载与故障恢复使用 SWD。

本项产出：固件版本记录、参考 target 选择理由、烧录及内存布局说明，以及原始 target 的构建结果。

依据：[AM32 官方仓库](https://github.com/am32-firmware/AM32)、[目标定义](https://github.com/am32-firmware/AM32/blob/main/Inc/targets.h)。

## 2. 确定桥臂控制逻辑

优先研究 DRV8323S 的 6x PWM 模式。MCU 的六路控制分别对应 INHA/INLA、INHB/INLB、INHC/INLC，不能当作三相始终连续输出的普通 PWM 使用。

需要为每个换相步骤定义：哪个相输出 PWM、哪个相低侧导通、哪个相上下管均关断以提供反电动势检测所需的悬空状态；并核对逻辑电平、互补输出与死区。

例如一个步骤可表达为 U 相 PWM、V 相低侧导通、W 相悬空。实际 U/V/W 与 AM32 A/B/C 的映射必须在表中统一，不能只按原理图名称推断。

本项产出：六步换相状态表、定时器通道候选、DRV 输入真值表对应关系，以及上电/复位/停机时的安全状态定义。

依据：[AM32 G071 换相实现](https://github.com/am32-firmware/AM32/blob/main/Mcu/g071/Src/phaseouts.c)、[DRV8323 数据手册 6x PWM 模式](https://www.ti.com/lit/ds/symlink/drv8323.pdf)。

## 3. 确定反电动势检测接口

需要明确三相分压后信号、比较参考信号、比较器输入与选择方式、极性、RC 滤波和钳位保护。比较参考可如何实现，必须随所选硬件目标和检测方式一并确定，不能在本清单中提前假定已选定某一种中性点电路。

当前 AM32 G071 源码会按换相步骤切换比较器输入，因此应优先保持其可兼容的比较器检测路径。分压网络需覆盖满电以及预期母线尖峰，并满足比较器模拟输入范围；5V 容忍 GPIO 不能据此视为可直接承受模拟相电压。

本项产出：反馈连接框图、输入/参考引脚候选、分压及滤波计算项、比较器选择与极性配置。核心完成标准是悬空相的实际电压变化能沿正确的硬件和固件路径触发检测。

依据：[G071 比较器源码](https://github.com/am32-firmware/AM32/blob/main/Mcu/g071/Src/comparator.c)、[STM32G071 数据手册](https://www.st.com/resource/en/datasheet/stm32g071cb.pdf)。

## 4. 分配 DShot、SPI、故障和调试资源

| 信号组 | 需要确定的内容 |
| --- | --- |
| 六路桥臂控制 | MCU 焊盘号、GPIO、TIM1 通道及复用、有效电平 |
| 反电动势与参考 | 三相检测输入、比较参考输入、比较器输入选择及极性 |
| DShot | 输入引脚、捕获定时器、DMA、对应 bootloader 输入 |
| SPI | SCLK、SDI、SDO、nSCS；引脚复用、SPI 时序、读回及上拉 |
| ENABLE | 驱动器唤醒/关断控制，复位期间的确定状态 |
| nFAULT | 开漏上拉、中断资源、故障后的动作与恢复条件 |
| 电流和母线电压 | ADC 通道、采样顺序、比例、零点与量程 |
| 温度检测 | 采用MCU内部温度通道，不增加外部NTC；功率器件温升在台架外部测量，PA0备用 |
| SWD 和恢复 | SWDIO、SWCLK、NRST、3V3、GND；核对调试供电方式 |
| UART、状态灯 | PB6/GND必须引出作遥测和开发日志，发送模式、缓存及DMA调度待适配；PB7保持反电动势用途 |

已经发现的具体资源约束：AM32 HARDWARE_GROUP_G0_A 参考布局使用 PA7 作低侧控制，ST 复用表同时列出 PA7 的 SPI1_MOSI 功能。若采用该参考布局，就必须为 SPI 选择不冲突的组合，或明确修改换相引脚；PA7 不能同时承担这两个用途。该发现用于指导分配，不代表已经选定 G0_A 为本板最终目标。

本项产出：《MCU 引脚与资源分配表》。表中应包含网络名、MCU GPIO/物理焊盘号、外设与 AF、连接对象、方向、上电状态、上拉/下拉及对应固件定义。用 UFQFPN48 封装逐项核对，包含底部裸焊盘EP接地要求，完成定时器、DMA和引脚冲突检查。

## 5. 明确电流采样、保护与驱动初始化

优先研究单低边采样，但先画出采样电阻、三桥臂回流、输入电容和控制地的连接关系。明确测到的电流在 PWM 各阶段代表什么，再决定采样、滤波和限流算法。

确定 DRV 放大器接线、未用通道处理、VREF、增益、零电流偏置、输出方向以及 ADC 通道；按 AM32 实际电流换算修改参数或逻辑。2mΩ、≥3W 仍按候选落实封装与热设计。

故障路径分别说明：驱动器内部快速保护如何动作，MCU 如何响应 nFAULT，平均限流如何运行，失去 DShot 或复位时如何使桥臂进入安全状态。过流阈值、消隐与故障恢复策略需要有计算或后续实测依据。

驱动初始化先定义为：复位时保持桥臂控制无效；按数据手册唤醒时序使驱动器可通信，同时保持 INHx/INLx 全低；完成 SPI 配置、必要校准和读回检查；确认故障状态及有效控制条件后才允许换相。具体步骤以选定寄存器和器件时序完成核对，不预设 ENABLE 为低时 SPI 一定可用。

本项产出：采样拓扑、ADC 换算定义、驱动器寄存器配置表及故障状态流程。

## 6. 本轮完成标准

1. AM32 参考版本与构建方法可重复，原始参考 target 构建成功。
2. 新板目标定义与引脚表相互一致，关键资源无冲突。
3. 六步换相、悬空检测、电流反馈和故障关断均有明确的信号路径。
4. bootloader、应用和参数区的布局已核对。
5. 新目标的适配修改清单完整，并进行能完成的编译检查；编译通过不能代替硬件验证。

近期应形成四份可审查成果：引脚与资源表、反馈/采样连接定义、DRV 配置及故障流程、AM32 目标适配记录。

## 7. 接着进入完整原理图

接口定义完成后，按模块展开：MCU 最小系统与调试接口；3.3V Buck 及滤波；DRV 电荷泵/驱动供电与六路栅极外围；三相 MOSFET 功率桥；反电动势、电流、母线电压和温度反馈；输入储能、保护、外接焊盘和测试点。

各模块可并行做参数准备，但互相关联的控制与反馈连接应采用本轮确定的接口。原理图审查与外围 BOM 完成后，再进入 PCB 布局布线。
